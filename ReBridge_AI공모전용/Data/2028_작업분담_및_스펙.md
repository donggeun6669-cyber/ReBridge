# 2028 시행계획 데이터 추출 — 작업 분담 & 공통 스펙

> 작성: 2026-06-03 (메인 창)
> 목적: 213개 대학 2028 시행계획 PDF에서 전형 상세필드를 추출해, 기존 `admissions.json`(2028 baseline) 보강용 **patch 파일**을 만든다.
> 이 문서는 3개 작업자(메인 Claude / Sonnet 창 / Codex)가 **공통으로 따르는 규칙**이다.

---

## 0. 절대 규칙 (위반 금지)

1. **`admissions.json` / `universities.json` / `results_2025*.json` 직접 수정 금지.** 결과는 각자 **별도 patch 파일**에만 쓴다. 병합은 메인이 한다.
2. **추측 금지.** PDF에 없는 값은 `null`. 잘못된 값은 빈 값보다 나쁘다.
3. **모든 행에 `source` 기록** (예: `"2028 국민대 시행계획 p.21"`).
4. PDF는 **텍스트 레이어 있음** → `pdfplumber`(좌표 기반 표 추출) 사용. `get_text()` 단순추출은 한글 순서가 깨지니 주의.
5. **캠퍼스 분리**: 파일명 `[본교]/[제2캠퍼스]/[분교]` 별로 별개 univId 후보로 취급(아래 4 참조).

## 1. 입력 위치

```
src/data/pdf_sources/2028/<대학명>[지역][캠퍼스]_2028_시행계획(1차수).pdf
```

지역은 파일명 `[지역]` 태그로 식별. glob 예: `*\[서울\]*.pdf`

## 2. 출력 스키마 — patch 행 (JSON 배열)

한 전형 = 한 행. 기존 admissions.json 행과 동일 키로 맞춘다.

```jsonc
{
  "univId": "kookmin",            // 기존 universities.json과 매칭(4번 규칙). 못 찾으면 "u2028_<순번>" 임시 + needsUnivId:true
  "univName": "국민대학교",
  "campus": "본교",                // 본교/제2캠퍼스/분교
  "region": "서울",
  "phase": "수시",                 // 수시 | 정시
  "admissionType": "학생부종합",    // 학생부종합 | 학생부교과 | 논술 | 실기/실적 | 수능위주
  "admissionName": "국민프런티어",  // 실제 전형명
  "unit": null,                    // 모집단위(요약표 단위면 null)
  "recruitCount": 320,             // 모집인원(전형 합계). 단위별이면 합계 or null
  "evalMethod": "1단계 서류100%(3배수), 2단계 1단계70%+면접30%", // 전형방법·비율 원문 요약
  "interview": true,               // 면접 유무
  "csatMinimum": "없음",           // 수능최저("국수영탐 중 2개합7" 등 원문 / "없음")
  "gedEligible": "가능",           // 가능 | 불가 | 조건부 (5번 규칙)
  "gedIneligibleReason": "",       // 불가/조건부 사유(차갑지 않게)
  "gedReflection": "서류평가",      // 검정고시 성적 반영 방식(비교내신 환산/서류평가/수능 등)
  "comparativeGrade": "",          // 비교내신 환산식/표 원문 (6번 규칙) — 최우선 가치 필드
  "note": "",
  "source": "2028 국민대 시행계획 p.21",
  "status": "confirmed_detail",    // PDF에서 직접 확인 → confirmed_detail
  "sourceYear": 2028
}
```

- 검정고시생이 **지원 불가**한 전형도 행으로 남긴다(`gedEligible:"불가"` + 사유). 앱이 "어려운 전형"으로 보여줌.

## 3. 추출 대상 전형 범위

- 수시(학생부종합·학생부교과·논술·실기) + 정시(수능위주·실기) **전부**.
- 정원외(농어촌·기회균형·특성화고 등)는 `admissionType` 유지하되 `note`에 "정원외" 표기. 검정고시 불가 많음.

## 4. univId 매핑 규칙

1. `universities.json`(351개)에서 **대학명 일치**로 찾는다(공백·"국립"·"학교" 제거 후 비교).
2. 캠퍼스가 다르면(제2캠퍼스/분교) 본교와 다른 전형이므로, 기존에 캠퍼스 구분 univId가 있으면 그걸, 없으면 본교 univId + `campus` 필드로 구분.
3. 매칭 실패 시 `univId:"u2028_<3자리순번>"`, `needsUnivId:true` 플래그 → 메인이 최종 정리.

## 5. gedEligible 판정 규칙 (검정고시 지원 가능 여부)

PDF **지원자격** 항목을 읽고 판정:

- **불가**: "검정고시 ... 지원할 수 없음" 명시 / "고등학교 졸업(예정)자"만 허용 / 학교장추천·재학생 한정 / 학생부 필수로 검정고시 평가 불가.
- **가능**: "검정고시 합격자" 명시 허용 / "고등학교 졸업(예정)자 또는 동등 이상 학력" / 수능위주(정시)는 대부분 가능.
- **조건부**: 검정고시 가능하나 비교내신·서류 등 제약 → `gedIneligibleReason`에 사유.
- 애매하면 `gedEligible:"조건부"` + reason "지원자격 추가확인 필요", `note`에 원문 인용.

`gedReflection`: 교과=비교내신 환산 / 종합=서류평가 / 정시=수능 / 논술=논술+(최저).

## 6. comparativeGrade (비교내신 환산식) 추출 — ★최우선

기존 0/1007 채움. Phase 2 점수엔진의 핵심 입력값.

- PDF에서 키워드로 섹션 탐색: **"비교내신", "검정고시", "동등학력", "환산", "산출"**.
- 환산표/산식을 **원문 그대로** 옮긴다(예: "검정고시 평균 98점↑→1등급, 96↑→2등급..." 또는 "교과 등급 = (검정고시 환산점수) 적용, 별도 산식 표 p.45").
- 표가 길면 핵심 구간 + `source` 페이지. 학교마다 다르므로 **있는 그대로**, 없으면 `null`.

## 7. pdfplumber 사용 팁

```python
import pdfplumber
with pdfplumber.open(path) as pdf:
    for i,page in enumerate(pdf.pages):
        for tbl in page.extract_tables():
            ...   # 전형요약표: 전형명/모집인원/전형방법/수능최저 열
        txt = page.extract_text()  # 지원자격·비교내신 prose
```

- 전형 **요약표**(보통 앞쪽 "전형요약"/"모집인원" 페이지)에서 구조필드를, **지원자격/유의사항** 페이지에서 gedEligible·comparativeGrade를 얻는다.
- 느린 PDF는 페이지 범위를 키워드로 먼저 좁혀라.
