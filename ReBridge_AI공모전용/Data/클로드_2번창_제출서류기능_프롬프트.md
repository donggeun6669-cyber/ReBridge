# 클로드 2번 창 작업 지시 — 「학교별 제출서류」 기능 (전부 신규 파일, 충돌 0)

> 작성일: 2026-06-03
> 목적: ReBridge에 검정고시생용 "전형별 제출서류 체크리스트" 기능 추가.
> ⚠️ **이 작업은 메인 창(나)·Codex와 파일이 절대 겹치면 안 됨.** 아래 "건드리지 말 것" 목록 엄수.

---

## 0. 프로젝트 맥락 (먼저 이해)

- ReBridge = 검정고시생/학교 밖 청소년이 "담임처럼" 대학 입시를 안내받는 React(Vite) 앱.
- 루트: `ReBridge_AI공모전용/Application_main_codes/`
- 규칙기반(AI 추론 없음). 데이터는 JSON 모듈 import. 디자인 톤 = 토스풍(둥근 카드, 부드러운 그림자, 보라 brand 컬러).
- **추측 주입 금지**: 확실치 않은 서류는 "모집요강 확인 필요"로 표기. 학교마다 다른 세부는 단정하지 말 것.

## 1. 절대 건드리지 말 것 (메인 창이 동시 수정 중)

`src/App.jsx`, `src/main.jsx`, `src/styles.css`, `src/components/{ExploreScreen,DetailScreen,ResultsScreen,ProfileScreen,HomeScreen,BottomNav,MyPageScreen,RoadmapScreen,GuideScreen}.jsx`, `src/lib/{scoreEngine,analysis,roadmap,schedule}.js`, `src/data/*.json`.

→ **읽기는 OK(스키마 파악용), 쓰기는 금지.** 통합(라우팅·네비·Detail 임베드)은 메인이 한다.

## 2. 만들 것 — 신규 파일만

### (a) `src/lib/documents.js` — 규칙기반 제출서류 엔진
검정고시생 기준으로 (phase, admissionType, gedEligible, interview, csatMinimum)를 받아 제출서류 체크리스트를 반환.

```js
// 입력: adm 행 { phase, admissionType, admissionName, gedEligible, interview, csatMinimum, comparativeGrade }
// 출력: { common: [...], byType: [...], notes: [...], confidence: 'general'|'check' }
export function getDocuments(adm) { ... }
```

근거 있는 일반 규칙만(검정고시생 공통):
- **공통**: 검정고시 합격증명서, 검정고시 성적증명서, 응시원서/지원서, (해당 시)주민등록초본.
- **학생부종합**: 자기소개서는 **2024학년도부터 전면 폐지**(넣지 말 것). 활동 증빙은 대학별 상이 → "대학별 제출서류는 모집요강 확인" note.
- **학생부교과/비교내신**: 검정고시 성적이 내신으로 환산되므로 별도 내신 서류 없음 → 그 점을 안내 문구로.
- **논술/실기**: 해당 고사 응시(서류보다 시험). 실기는 "실기 종목별 증빙 모집요강 확인".
- **수능위주(정시)**: 수능 성적이 핵심, 제출서류 최소.
- **면접 있음**: 면접 대상 안내(서류는 아님, note로).
- 불확실/대학별 상이한 건 전부 `notes`에 "모집요강에서 확인하세요"로, `confidence:'check'`.

**중요**: 학교 고유 서류 목록 데이터가 없으면 만들어내지 말고, 전형 유형 기반 일반 안내 + "모집요강 확인"으로 정직하게. (자료 없으면 "자료 없음/모집요강 확인"을 명시하는 게 이 앱의 원칙.)

### (b) `src/components/DocumentsChecklist.jsx` — 임베드용 컴포넌트
- props: `{ adm }` (admissions 행 1개). `getDocuments(adm)` 호출해 체크리스트 렌더.
- 체크박스는 로컬 상태로 토글 가능(localStorage 저장은 선택, key `rebridge_docs_<univId>_<admissionName>`).
- 자료가 일반규칙 기반이면 하단에 "학교별 상세 서류는 모집요강에서 꼭 확인하세요" 안내 배지.
- **자체 className 네임스페이스 `doc-*` 사용** (예: `.doc-card`, `.doc-item`, `.doc-check`, `.doc-note`).

### (c) `src/styles.documents.css` — 이 기능 전용 CSS
- 위 `doc-*` 클래스만 정의. 토스풍(흰 카드, radius 16px, 부드러운 그림자, brand=#7C5CFC, brand-deep=#5B3FD6, brand-tint=#F1ECFE, text=#1A1726, text-sub=#7C7689, green=#1E8C77).
- `DocumentsChecklist.jsx`에서 `import '../styles.documents.css';` 로 직접 import(전역 styles.css 수정 금지).

### (d) `src/components/DocumentsScreen.jsx` — (선택) 독립 화면
- props `{ goTo, univId, admissionName }`. 특정 전형의 제출서류를 풀스크린으로. 내부에서 `DocumentsChecklist` 재사용.
- 라우팅은 메인이 붙임. 이 파일은 export만 잘 해두면 됨.

## 3. 데이터 스키마 참고 (읽기 전용)

`src/data/admissions.json` 행 예: `{ univId, phase('수시'|'정시'), admissionType('학생부종합'|'학생부교과'|'논술'|'수능위주'|'실기'|'일반(서류)'), admissionName, gedEligible('가능'|'조건부'|'불가'), interview(bool/null), csatMinimum(string/null), comparativeGrade(string/null) }`.

## 4. 산출·검증

- `npm run build`(또는 `npx vite build`)가 **에러 없이** 통과해야 함(이 파일들만으로).
- 컴포넌트가 어떤 adm 행을 받아도 깨지지 않게 null 가드.
- 작업 끝나면 `Data/제출서류기능_인계.md`에 ① 만든 파일 목록 ② `getDocuments` 시그니처/반환형 ③ 메인이 해야 할 통합 단계(라우트/네비/Detail 임베드 위치 제안)를 적어 둘 것.
