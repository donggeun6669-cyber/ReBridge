## 효율 원칙 (1차와 동일)

- **전부 결정론적 파이썬.** LLM 토큰 0이 목표.
- LLM은 segmentation(B)에서 대학 경계가 도저히 규칙으로 안 잡히는 **소수 페이지에만** mini급으로. 그마저도 "페이지 일부 텍스트"만 전달, PDF 통째 금지.
- 원본 `results_2025.json`은 **보존**(덮어쓰기 금지). 산출물은 별도 파일.
- `admissions.json`·`universities.json` **직접 수정 절대 금지.**

## 복붙 프롬프트

```
[작업] results_2025.json(1차 추출, 20,830행)의 검수 결함 4가지를 결정론적으로 정제하고 앱 조인 준비를 끝낸다.
원본은 보존, admissions.json/universities.json 직접수정 금지, 토큰 최소.

[입력]
- src/data/results_2025.json (1차 결과)
- src/data/reports/results_2025_unmatched.json
- src/data/universities.json (univId/name/region), admissions.json (2028 전형구조)
- src/data/pdf_sources/ (집/작업PC 로컬, git 제외) — B의 재처리에 필요

[작업 A] 등급/점수 분리행 병합  ← 행수 최우선 축소
- 현상: 같은 합격선이 한 행은 cutGrade만, 다른 행은 cutScore만 갖고 둘로 쪼개져 있음.
- 병합키: (univId, phase, admissionType, admissionName, unit, cutType, year, sourceFile, sourcePage)
- 키가 같은 행들을 1행으로 합쳐 cutGrade·cutScore를 한 행에 둘 다 채운다.
- 충돌(같은 키인데 grade가 2개 등): 값이 다르면 합치지 말고 양쪽 보존 + note에 "병합충돌" 표기, confidence 한 단계 강등.

[작업 B] 누락 핵심대학 복구  ← 가장 중요
- 전북대(jbnu)·충남대(cnu)·중앙대(cau)·인하대(inha)·한양대(hanyang)가 universities.json엔 있으나 results에 0행, unmatched에도 없음.
- 원인 가설: 멀티대학 PDF에서 페이지→대학 구분(segmentation) 오류로 인접 대학에 흡수됨.
- 해결: 각 PDF에서 대학 경계를 다시 인식한다. 보통 "○○대학교" 표제/목차/페이지 헤더가 경계. 페이지별 univId를 재할당하고 영향받은 행의 univId/univName을 교정.
- 우선 재처리 대상: 서울_1~4, 충남_1·2, 전북_1·2 (그 다음 경기·부산 등 다대학 PDF).
- 규칙으로 경계가 안 잡히는 페이지만 LLM(mini)에 "이 페이지가 어느 대학인지"만 소량 질의.
- 복구 후 핵심 15개 대학(서울권+거점국립) 각 행수를 리포트에 표로.

[작업 C] unit(학과/모집단위) 문자열 정제
- PDF 줄바꿈으로 생긴 내부 공백/깨짐 정리: "스포츠레 저학전공"→"스포츠레저학전공", "기계의용· 메카트로닉스공학과"→"기계의용·메카트로닉스공학과".
- 규칙: 한글 사이 단독 공백 제거(단, 의미 있는 공백은 보존하는 화이트리스트 운영), 중복/꼬리 공백 trim, 가운뎃점 주변 공백 정리.
- 적용 전/후 예시와 규칙을 reports에 남길 것.

[작업 D] 수치 스케일 검증·이상치 플래그
- cutGrade는 1.0~9.0만 허용. 범위 밖은 cutScore로 잘못 들어간 것일 수 있으니 재분류 시도, 안되면 제외+로그.
- cutGrade 9.0(52건) 개별 확인: 실제 9등급인지, 점수 오인식인지.
- cutScore는 cutType/전형별 스케일 구분: 백분위(0~100)·표준점수·환산점수(임의 만점). 스케일을 note에 명시.
- 명백한 모순(예: '최종등록' 백분위인데 22.2처럼 비현실적 저값)은 confidence를 low로 강등하고 note에 "스케일의심".

[산출물]
- src/data/results_2025_clean.json (A~D 적용한 정제본. 원본 results_2025.json은 그대로 둠)
- src/data/reports/results_2025_clean_report.md:
  - before/after 행수(A 병합 효과), B 복구된 대학·행수표, C 정제 규칙·예시, D 이상치 처리 건수
  - **조인 준비도**: results_clean의 (univId, admissionType) 조합이 admissions.json과 겹치는 비율 = 합격선을 붙일 수 있는 2028 전형 수. 핵심 10개 대학 커버리지표(대학×전형유형×합격선 유무).

[수용 기준]
- 행수가 A 병합으로 유의미하게 감소(중복 grade/score 행 사라짐).
- 전북대·충남대·중앙대·인하대·한양대가 results_clean에 0행이 아님(복구됨).
- unit에 내부 공백 깨짐이 사라짐.
- cutGrade는 전부 1.0~9.0. 이상치는 제외 또는 note 플래그됨.
- 리포트에 조인 준비도와 핵심10 커버리지표가 있음.
- 토큰: A·C·D는 LLM 0회. B의 segmentation 모호 페이지에만 소량.
```
