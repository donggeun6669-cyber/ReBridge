## 2. 격차 = 다음 작업 (V2 신규 데이터 4종)

기획서 V2의 정량 분석 기능별로 필요한 데이터와 작업.

### 🔴 작업 A. 비교내신 환산표 (`comparativeGrade`) — **최우선, 현재 0%**
- **무엇:** 검정고시 평균점수 → 내신 등급 환산. **대학마다 식이 다름.**
- **형태 제안:** 단순 문자열로는 계산이 안 됨. 계산 가능한 구조로 신규 저장 권장:
  ```jsonc
  "comparativeGrade": {
    "type": "table",            // table | formula
    "bands": [                  // 점수구간 → 등급
      { "min": 95, "grade": 1.0 },
      { "min": 90, "grade": 2.0 },
      { "min": 80, "grade": 3.0 }
    ],
    "appliesTo": "학생부교과",   // 어떤 전형에 쓰이는지
    "source": "OO대 2028 시행계획 p.XX"
  }
  ```
- **출처:** 각 대학 모집요강의 "검정고시 성적 환산", "비교내신", "동등학력자 성적 산출" 항목 (보통 표 또는 식).
- **주의:** 환산은 교과(내신) 전형에서 주로 쓰인다. 학종/논술은 환산이 없거나 다르게 적용 → 전형별로 구분.

### 🔴 작업 B. 합격선 점수 (신규 필드) — "몇 문제 더"의 핵심
- **무엇:** 대학·전형·학과별 **작년(들) 입시결과 합격선** (예: 70%컷 등급, 평균 등급/점수).
- **형태 제안:** 연도 명시한 신규 필드.
  ```jsonc
  "admissionResult": {
    "year": 2025,
    "cut70": 2.3,        // 70%컷(등급) 등
    "avg": 1.9,
    "unit": "경영학과",
    "source": "..."
  }
  ```
- **출처(확보됨):** 팀이 보유한 **2025학년도 지역별 입시결과 PDF**가 1차 출처다.
  (2028 시행계획 PDF에는 미래 입시라 합격선이 없다 — 합격선만은 이 2025 입결 PDF에서 뽑는다.)
  - ⚠️ **이 PDF들은 현재 작업 PC가 아니라 집 컴퓨터에 있고**, `pdf_sources/`·`text/`는 git 제외라 repo에도 없다.
    → 집에서 추출하거나, PDF를 작업 PC `pdf_sources/`로 옮겨 추출 후 **JSON 결과만 커밋**한다.
  - 연도(2025)·출처를 `admissionResult.year`/`source`에 반드시 기록. 2028 전형 구조와 학과·전형명을 매칭해 붙인다.
- **이게 가장 차별적인 데이터.** 핵심 대학부터 소량이라도 정확히.

### 🔴 작업 C. 모집인원·모집단위 (`recruitCount` 9% → ↑, `unit` 0% → ↑)
- **무엇:** 전형별·학과별 모집인원("칸수"). `unit`(학과)이 비면 칸수 분석이 무의미.
- **출처:** 2028 시행계획 PDF의 전형별 요약표(이미 보유). `confirmed_detail` 8개 대학은 이미 됨.
- **방법:** `extract_tier1_summary_tables.py`(pdfplumber) 결과를 대학별로 검수 후 승격. 가천대 방식이 성공 사례.

### 🔴 작업 D. 제출서류 (신규 필드)
- **무엇:** 전형별 제출서류 목록(검정고시 합격증명서, 자기소개서, 추천서 가능여부 등).
- **형태 제안:** `"documents": ["검정고시 합격증명서", "자기소개서"]`
- **출처:** 모집요강 "제출서류" 항목.
- **검정고시 관점 핵심:** "학교장 추천서/학생부 필요" 같은 **검정고시생이 못 내는 서류**가 있으면 표시 → `gedEligible`/`gedIneligibleReason`과 교차검증.

## 3. 대학 우선순위 (상세 확장)

`CODEX_다음작업_인계.md`의 다음 후보를 그대로 이어간다. confirmed_detail 8개 → 목표 18개.

**다음 1순위 (상세·모집인원):** 국민대 → 인하대 → 한양대 → 서울과기대 → 경북대 → 충남대 → 전북대

## 4. 작업 원칙 (인계 문서 계승 — 반드시 지킬 것)

1. **상세 후보를 바로 `admissions.json`에 넣지 말 것.** 반드시 검수 후 병합. (수능최저·모집인원·합격선은 틀리면 사용자 안내가 즉시 틀려진다.)
2. PDF 표 구조가 대학마다 달라 자동 병합 위험. 텍스트 후보엔 목차번호·모집단위가 전형명처럼 잡히는 잡음 있음.
3. 병합 시 `status`로 신뢰도 구분 유지(`baseline` < `confirmed` < `confirmed_detail`). 합격선처럼 외부출처는 별도 출처·연도 기록.
4. 신규 필드(합격선·제출서류·구조화 환산표)는 먼저 `SCHEMA.md`에 정의를 추가하고 코딩 창과 합의 후 채운다.
