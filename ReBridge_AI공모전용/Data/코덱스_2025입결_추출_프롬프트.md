# 코덱스용 프롬프트 — 2025 입시결과(합격선) PDF 추출

> 작성일: 2026-06-02
> 용도: 집 PC에서 코덱스로 2025 지역별 입시결과 PDF → 합격선 구조화 JSON 추출
> 관련: `데이터현황_및_추가분석_지시_V2.md` 작업 B

---

## 효율 전략 (먼저 읽기)

- **PDF 본문을 LLM에 통째로 넣지 않는다.** 합격선은 표 안의 숫자라, 추출은 **파이썬(pdfplumber/PyMuPDF)으로 로컬 = 토큰 0**.
- **키워드 앵커링**으로 합격선이 있는 페이지만 골라 파싱 → 빠르고 싸다.
- LLM은 **표 헤더↔값 매핑이 모호한 소수 행 보정에만** 소량 사용.

## GPT 모델 추천

| 단계 | 모델 | 이유 |
| --- | --- | --- |
| 스크립트 설계·표 파싱 로직 작성 | **최상위 코딩 모델**(현행 기준 GPT‑5.1‑Codex, reasoning=high) — 1회성 | 도구를 만드는 데만 강한 추론 |
| PDF 대량 추출(1~4단계) | **모델 안 씀(파이썬)** | 토큰 0, 결정론적 = 안전·정확 |
| 모호 케이스 보정(5단계) | **mini급 저가·고속 모델**, 소량 배치 | 비용 최소 |

> 핵심: 비싼 모델은 "도구를 만드는 데", 추출 자체는 결정론적으로.

---

## 복붙 프롬프트

```
[작업] 2025학년도 지역별 "입시결과(합격선)" PDF → 대학·전형·학과별 합격선 구조화 JSON 추출.
토큰을 최대한 아껴서(키워드 앵커 + 결정론적 파싱) 안전·정확하게.

[전제/입력]
- PDF 원본: ReBridge_AI공모전용/Application_main_codes/src/data/pdf_sources/ 에 둔다(2025 입결, 지역별). 이 폴더는 git 제외 → PDF는 커밋 안 함, 결과 JSON만 커밋.
- 기존 데이터:
  - universities.json (351개): univId, name, region, establishment, lat, lng, kind
  - admissions.json (1007행, 2028 기준): univId, phase(수시/정시), admissionType(학생부종합/학생부교과/수능위주/논술/실기/일반(서류)), admissionName, unit, status(baseline/confirmed/confirmed_detail) 등
- 합격선은 2028 모집요강이 아니라 이 2025 입결 PDF에서만 나온다. 2028 전형 구조와 "조인"하는 게 목표.

[목표 산출물]
- src/data/results_2025.json (신규, 검수용 별도 파일 — admissions.json은 절대 직접 수정 금지):
  [{
    "univId": "...", "univName": "...",
    "phase": "수시|정시", "admissionType": "...", "admissionName": "...",
    "unit": "경영학과",                 // 모집단위/학과
    "year": 2025,
    "cutType": "70%컷|평균|최종등록|최저",  // 무엇의 컷인지 반드시 명시
    "cutGrade": 2.3,                    // 등급이면 (0.0~9.0). 없으면 null
    "cutScore": null,                   // 점수/표준점수/백분위면. 단위는 note에
    "recruitCount": 30, "competition": 12.3,
    "region": "서울",
    "sourceFile": "서울_2025입결.pdf", "sourcePage": 12,
    "confidence": "high|mid|low"
  }, ...]
- reports/results_2025_report.md: PDF별 처리 결과, 매칭률, confidence 분포, unmatched(대학/전형/학과 매칭 실패) 목록.

[파이프라인 — 결정론 우선, LLM 최소]
0) 인벤토리: pdf_sources/ 스캔. 파일명에서 지역·대학 추정. 페이지수만 먼저 집계(본문 안 읽음).
1) 로컬 추출(LLM 미사용): pdfplumber로 표 추출, 실패 페이지만 PyMuPDF 텍스트. 기존 extract_pdf_text.py / extract_tier1_summary_tables.py 재활용.
2) 키워드 앵커링: 다음 앵커가 든 페이지만 파싱 대상으로 좁힌다 →
   ["입시결과","합격","최종","등록","충원","70%","80%","평균","등급","환산","경쟁률","모집","수시","정시"].
   앵커 없는 페이지는 스킵(토큰·시간 절약).
3) 정규식 행 파싱: (학과/모집단위, 전형명, 합격선숫자, 모집인원, 경쟁률) 후보 추출.
   - 등급 패턴: 0.0~9.0 소수 / 점수: 0~100·표준점수·백분위 구분. cutType으로 명시.
4) 정규화·매칭: 대학명→univId(universities.json), 전형명→admissionType, 학과→unit.
   매칭 점수화 → confidence(high/mid/low). 매칭 실패는 results_2025.json에 넣지 말고 unmatched로 따로.
5) LLM 보정(선택, 소량만): confidence=low 또는 표 헤더↔값 매핑이 모호한 행만 작은 배치로.
   해당 "페이지 일부 텍스트"만 전달(PDF 통째 금지). mini급 모델 사용.
6) 출력 + 리포트. admissions.json 병합은 별도 작업(검수 후 promote_*.py 패턴).

[안전·정확 규칙]
- 직접 병합 금지. confidence로 신뢰도 표기. 핵심 대학(서울권+거점국립)부터 high로 확정.
- 등급 vs 점수 vs 백분위 혼동 금지 → cutType·단위 항상 기록.
- 학과/전형명 표기 흔들림(예: "경영"/"경영학과"/"경영학부") 정규화 규칙을 reports에 남길 것.
- 한글 깨짐/OCR 필요 PDF는 따로 표시, 무리한 추측 금지.
- year=2025, sourceFile·sourcePage 반드시 기록(검증 가능하게).

[수용 기준]
- pdf_sources의 PDF가 results_2025.json + unmatched + report로 빠짐없이 분류됨.
- 핵심 10개 대학은 사람이 PDF와 대조해 검증 가능한 수준의 high confidence 행 보유.
- 토큰 사용: 1~4단계는 LLM 0회, 5단계만 소량.
```

## 집에서 시작 순서

1. 2025 입결 PDF를 `src/data/pdf_sources/` 에 복사 (git에 안 올라감 — 정상).
2. 위 프롬프트를 코덱스에 전달, 스크립트 작성 시킴.
3. 나온 `results_2025.json` + `reports/results_2025_report.md` **검수**.
4. 핵심 대학부터 high confidence 확인되면 그때 admissions/앱에 연결(별도 작업).
