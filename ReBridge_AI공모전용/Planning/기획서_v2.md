## 0. V1 → V2 무엇이 바뀌었나

| | V1 | **V2 (이번 방향)** |
| --- | --- | --- |
| 정체성 | "지원 가능한 대학을 찾아주는 앱" | **"검정고시 전용 입시 분석 엔진" (진학사/유웨이의 검정고시판)** |
| 깊이 | 지원 가능 여부 + 전형 설명 | **점수 → 비교내신 환산 → 합격선 비교 → "몇 문제 더" → 칸수 분석 → 제출서류**까지 |
| 대학 수 | 수도권·거점국립 우선 | **전국 거의 모든 대학** (현재 351개 보유, 확장) |
| 진로/직업교육 | 검토했으나 **이번 범위 제외** | 동일하게 **제외**. 검정고시 입시 한 우물만 깊게 판다 |

> **이번 스코프 락:** 검정고시 → 대학 입시. 직업교육·진로탐색·센터찾기는 만들지 않는다.

## 1. 우리가 비교하는 경쟁 서비스 — gumjung.co.kr ("검정고시로 대학가기")

검정고시 입시를 정확히 같은 영역에서 다루는 사이트가 이미 있다.
- 하는 일: 검정고시 점수 입력 → 비교내신 환산 → 수시 합격예측 → 추천/목표 대학 + FAQ
- **약점(= 우리 기회):**
  1. 점수를 **고정값**으로만 본다. "네 점수 = 합/불"로 끝. *어떻게 올릴지*가 없다.
  2. 비교내신 환산식을 **이미지로 숨겨** 결과만 던진다. 왜 그 등급인지, 어디가 유리한지 모른다.
  3. 차가운 계산기 톤. 검정고시생이 학교를 나오며 잃은 "담임"의 역할이 없다.

| 축 | gumjung | **ReBridge V2** |
| --- | --- | --- |

| 톤 | 계산기 | **담임 ("다음에 이거 해")** |

## 3. 핵심 기능 (3개 기둥)

### 기둥 1. 입시제도 — 점수 분석 엔진 (★ V2의 심장)

검정고시 과목별 점수를 입력하면, 전국 대학을 대상으로 다음을 보여준다.

**(1) 비교내신 환산 — 대학마다 "내 점수가 몇 등급인지"**
- 같은 점수라도 대학별 환산식이 달라 등급이 갈린다. 대학별로 환산 결과를 나열하고 **유·불리를 비교**한다.
  > "평균 88점 — A대 1.5등급 / B대 2.3등급 → **A대가 유리해요.**"
- "왜 이 등급인지"를 환산식과 함께 쉬운 말로 설명한다. (gumjung이 숨기는 부분)

**(2) 합격 가능성 — "합격선까지 몇 점 / 몇 문제"**
- 대학·전형별 합격선(작년 입시결과 기준)과 내 환산점수를 비교.
- 부족분을 **"몇 문제 더"로 번역** (앱의 시그니처 카피).
  > "합격선까지 0.4등급 부족 → **사회에서 2문제만 더** 맞으면 도달. 국어는 이미 만점권이라 효과 작아요."

**(3) 점수 = 레버 — 과목별·회차별 전략**
- 검정고시는 **과목별 점수**가 따로 나오고 **연 2회**다. 이걸 활용한다.
- 어느 과목을 올리면 환산점수가 가장 많이 뛰는지 짚어주고, **다음 회차(8월/4월)에서 목표 점수**를 제시한다. → 로드맵(기둥 2)과 직접 연결.

**(4) 칸수·모집 분석 (유웨이/진학사식)**
- 모집인원·(가능하면) 경쟁률·합격선 분포로 지원 난이도(소신/적정/안정)를 표시.

### 기둥 2. 개인 로드맵 (얼추 구현됨 — 보강)

- 현재: 오늘 날짜 기준 검정고시 회차 → 수시 원서 → 수능 → 면접 → 등록 단계와 D-day 자동 계산. (구현 완료)
- **보강 1 — 제출서류·절차 체크리스트:** 각 단계 안에 "검정고시 합격증명서, 사진, 응시원서…" 같은 준비물을 체크리스트로. (담임이 챙겨주던 것)
- **보강 2 — 점수 전략 연동:** 기둥 1의 "다음 회차 목표 점수"를 로드맵 검정고시 단계에 표시.

### 기둥 3. 둘러보기 (현재 모양만 — 재설계)

- 현재 문제: 대학만 하드코딩으로 나오고, 지역 검색이 제대로 안 됨.
- **재설계:** 실데이터(`universities.json` + `admissions.json`) 연결 → 전국 대학을 지역·전형·검정고시 가능 여부로 필터/검색. 지도(Leaflet, 좌표 보유) 연동.
- 카드는 기둥 1의 분석 요약(내 점수 기준 가능/유불리)을 함께 보여준다.

## 4. 결과 카드가 답해야 할 질문 (V1 계승 + V2 확장)

> ① 나, 여기 지원할 수 있어? → ② 어떤 전형으로? → ③ **내 점수면 합격선까지 얼마나? (몇 문제 더?)** → ④ **뭘 제출해야 해?** → ⑤ 그럼 지금 뭘 해야 해?

③④가 V2에서 새로 강화되는 축이다.

## 5. 데이터 — V2가 요구하는 것 (★ 별도 문서 참조)

V2의 신규 기능 대부분은 **현재 없는 데이터**를 필요로 한다. 상세 현황·격차·수집 지시는
`Data/데이터현황_및_추가분석_지시_V2.md` 참조. 요약하면:

| 기능 | 필요 데이터 | 현재 충진율 | 상태 |
| --- | --- | ---: | --- |
| 비교내신 환산 | `comparativeGrade` (대학별 환산표) | **0%** | 🔴 전무 |
| 합격/몇 문제 더 | 합격선 점수 (신규 필드) | **없음** | 🔴 필드 자체 없음 |
| 칸수 분석 | `recruitCount`(모집인원)·`unit`(학과) | 9% / 0% | 🔴 거의 없음 |
| 제출서류 | 제출서류 (신규 필드) | **없음** | 🔴 필드 자체 없음 |
| 검정고시 가능여부 | `gedEligible` 등 | 90%+ | 🟢 양호 |
| 전형방법·수능최저 | `evalMethod`·`csatMinimum` | 98% / 78% | 🟢 양호 |

> 즉 **검정고시 "가능 여부"는 잘 갖춰졌고, V2의 "정량 분석"에 필요한 데이터가 비어 있다.** 다음 데이터 작업의 최우선이 여기다.

## 6. 쉬운 언어·말투 원칙 (V1 계승, 변경 없음)

- "백분위 92" → "한 과목에서 2~3문제 차이예요"
- "기준 미달" → "조금만 더 하면 돼요. 두 문제 차이예요"
- 항상 결과 + **이유 + 다음 행동**. '불가'도 차갑지 않게 대안 제시.
- 격려 한 줄 ("검정고시까지 온 것만 해도 대단해요").

## 7. AI(Gemini) 활용 — 보조 (V1 계승)

- 기본 분석은 **규칙 기반** 우선(AI 없이도 결과가 나옴).
- Gemini는 "담임 한마디" 한 줄 코멘트, 자유 질문 답변 보조. 시연 안정성 우선이라 없어도 돌아가게.

## 8. 범위 (이번에 만드는 것 / 안 만드는 것)

**만든다:** 점수 분석 엔진(비교내신·합격선·몇 문제 더·칸수), 로드맵 보강(서류 체크리스트), 둘러보기 실데이터 재설계, 전국 대학 확장.

**안 만든다:** 직업교육·진로탐색, 센터 찾기, 회원가입/로그인, 푸시, 등록금/장학금.

## 9. 개발 우선순위 (V2)

| 순위 | 항목 | 선행 데이터 |
| --- | --- | --- |
| 1 | 둘러보기 실데이터 연결 + 지역 검색/필터 수정 | 이미 보유(351대학) |
| 2 | 결과 카드에 비교내신 환산 표시 | `comparativeGrade` 수집 필요 |
| 3 | "합격선까지 몇 문제 더" 분석 | 합격선 데이터 수집 필요 |
| 4 | 칸수·모집 분석 | `recruitCount`·`unit` 보강 |
| 5 | 제출서류 체크리스트 | 제출서류 데이터 수집 |
| 6 | 로드맵 서류 체크리스트 보강 | (콘텐츠 작성) |

> 1번은 데이터가 이미 있어 바로 가능. 2~5번은 데이터 수집이 선행돼야 한다(코덱스 작업).
