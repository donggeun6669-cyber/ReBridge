# 2단계 — Python 자동 추출기 현황 (2026-09-20 밤)

목표: 요강의 반복적인 표는 **Python 이 읽고**, AI(에이전트)는 **기계가 못 읽은 예외만** 맡는 구조로 바꾼다.
지금까지 요강 자료는 전부 에이전트가 한 줄씩 읽어 만든 것이라 335곳 중 38곳(칸 기준 6%)에 머물러 있었다.

## 만든 것

| 파일 | 하는 일 |
|---|---|
| `extract_offerings.py` | 요강·시행계획 PDF 에서 '모집단위 × 전형' 모집인원표를 찾아 offerings.jsonl 로 뽑는다 |
| `regression_merge.py` | 병합기가 손실·증식 없이 도는지 실제로 돌려 확인한다(7개 항목) |
| `work/auto_out/_exceptions.jsonl` | 기계가 확정하지 못한 문서·쪽·사유 목록 = **에이전트 작업 지시서** |

출력은 `work/auto_out/PY-OFF/<univId>/offerings.jsonl` 이고, 정본 반영은 기존 `merge_agent.py` 하나로만 한다.
**병합 경로를 새로 만들지 않았다.**

## 핵심 설계 — 산수로 검산되지 않으면 값으로 만들지 않는다

표를 찾았다고 바로 값으로 만들지 않는다. 두 가지 검산 중 하나를 통과해야 한다.

1. **가로 검산** — 행마다 `각 전형 인원의 합 == 그 행의 계`
2. **세로 검산** — 전형 열마다 `각 학과 인원의 합 == 맨 아래 합계 행의 값`

통과하면 `value_status: confirmed`, 검산할 합계가 아예 없으면 **값을 만들지 않고 예외 큐로 보낸다.**

왜 이렇게 했는가: 검산 없이 뽑으면 60개 문서에서 17,693건이 나왔는데 그중 산수로 확인된 것은 310건(1.8%)뿐이었다.
나머지를 정본에 넣으면 숫자만 부풀고 신뢰도는 떨어진다 — 2026-09-20 교차점검이 지적한 바로 그 실패다.

검산 장치가 실제로 잡아낸 것:
- 강원대 수시요강: 한 행에 여러 학과가 뭉쳐 들어가 인원이 어긋남 → 탈락
- 국민대 수시요강: 전형 이름이 `'25'`, 학과 이름이 `'※'` → 탈락
- 서울과기대: 학과 열 대신 **계열 열**(인문/자연)을 학과로 잡음 → 열 고르기를 '값이 서로 다른 정도'로 바꿔 해결

## 아직 쓸 수 없는 이유 — 정직하게

**기준을 조일 때마다 붙는 표와 떨어지는 표가 바뀐다.** 예를 들어 합계 행 인식을 넓혔더니
전체 검산 통과는 361 → 2,142건으로 6배 늘었지만, 그 전까지 통과하던 **강서대 2027 수시 표(경영학과 16명 — 원문 대조로 맞는 값)가 탈락**했다.

즉 지금 추출기는 "맞는 값만 남긴다"는 방향은 옳지만, **어떤 표가 통과할지가 안정적이지 않다.**
이 상태로 전체에 돌려 정본에 넣으면 대학마다 있다 없다 하는 자료가 생긴다.

그래서 **2026-09-20 밤 기준으로 이 추출기의 결과는 정본 DB 에 병합하지 않았다.**

## 정답 묶음이 바로 잡아낸 것 (2026-09-20 밤 신설)

`golden/offerings_golden.jsonl` 에 **사람이 원문을 직접 본 값** 5건을 넣고 `check_golden.py --db` 로 정본과 대조했다.

```
  맞음  강서대학교 2027 경영학과 · 일반학생 = 16명
  맞음  강서대학교 2027 경영학과 · 교과우수자 = 21명
  없음  명지대학교 2027 경영학부 · 교과면접 → 기대 18명. 이 값이 아예 안 나왔다
  없음  성균관대학교 2027 인문과학계열 · 탐구인재 → 기대 25명
  없음  성균관대학교 2027 인문과학계열 · 융합인재 → 기대 30명
  2 / 5 일치
```

**내일 입시 전문가에게 보여줄 세 대학 중 두 곳의 모집인원이 정본에 없다.**
에이전트가 그 대학의 자격·평가·최저는 뽑았지만 **모집인원표는 안 뽑았다.**
커버리지 6.1% 가 무슨 뜻인지 보여주는 가장 구체적인 증거다.

→ 다음 세션에서 이 3건을 먼저 채우고, 정답 묶음을 20~30건으로 늘린다.

## 전체 실행 결과 (2026-09-20 23:30~23:47, 869/873 문서)

| | 값 |
|---|---|
| 검산 통과해 값이 된 레코드 | **10,450건** (90개 대학) |
| 정답 묶음 대조 (`check_golden.py`) | **0 / 5 일치** |

**결론: 이 추출기의 출력은 쓸 수 없다.** 1만 건을 뽑았지만, 사람이 원문에서 확인한 값 5건 중
**단 하나도 재현하지 못했다.** 산수 검산은 통과했는데 정답은 못 맞춘다는 것은,
검산이 '표 안에서 앞뒤가 맞는지'만 보고 '그 표가 맞는 표인지'는 못 본다는 뜻이다.

정본 DB 는 같은 대조에서 5/5 이다(메인이 원문을 직접 보고 넣은 값이라서다).
**기계 추출 결과를 정본에 병합하지 않은 판단이 맞았다.**

## 다음에 할 일 (순서대로)

0. **왜 정답을 못 맞히는지 먼저 본다.** 강서대·명지대·성균관대 그 쪽에서 추출기가 무엇을 뽑았는지
   한 쪽씩 손으로 따라가 본다. 검산을 통과했는데 정답이 아니라면 '어느 표를 고르는가'가 틀린 것이다.
1. **고정 정답 묶음을 먼저 만든다.** 사람이 원문과 대조한 표 20~30개(대학·형식이 서로 다른 것)를 정답으로 두고,
   추출기를 고칠 때마다 이 묶음이 **전부** 통과하는지 확인한다. 지금은 이 안전망이 없어서 고칠 때마다 다른 데가 깨진다.
   (강서대 2027 경영학과 16명, 명지대 경영학부 18명, 성균관대 인문과학계열 탐구인재 25명 등 이미 원문 대조한 값이 출발점)
2. **선 없는 표**(149건) 대응: pdfplumber 의 `table_settings` 를 글자 좌표 기반(`text` 전략)으로 바꿔 재시도.
3. **합계가 없는 표**(395건): 합계 대신 다른 검산을 쓴다 — 같은 학과가 다른 쪽(전형별 상세)에 다시 나오면 그 값과 대조.
4. 통과한 표만 `merge_agent.py PY-OFF` 로 병합하고, 행 수 대조로 손실 0 확인.
5. 그 다음에 평가방법·일정·서류 추출기로 넓힌다. 환산표·수능최저는 문장이 섞여 있어 **에이전트가 계속 맡는 편이 낫다.**
