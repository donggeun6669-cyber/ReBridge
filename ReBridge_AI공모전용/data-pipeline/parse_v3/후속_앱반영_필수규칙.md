# 후속 앱 반영 필수 규칙 (parse_v3 → 앱) — 구현 명세, 이번 작업에서 구현하지 않음

- 작성: 2026-09-20, parse_v3 작업대 기준. **이 문서는 후속 구현 명세이며 점수 엔진·앱을 수정할 권한이 아니다.**
- 데이터 정본: `data-pipeline/parse_v3/work/parse_v3.sqlite` (필드 뜻은 `DATA_DICTIONARY.md`, 상태값은 `README.md`).
- 아래 ‘확인할 실제 사례’의 레코드 ID·쪽은 `reports/trial_report.md` 와 같은 정본에서 나온 것이다.

## 0. 네 가지 판정은 서로 독립이다

| 판정 | 결과 상태 | 근거 테이블 |
|---|---|---|
| A. 지원 자격 | 충족 / 미충족 / 조건 확인 필요 / 자료 확인 필요 | `eligibility_rule` + `eligibility_condition` |
| B. 공식 성적 산출 | 공식 기준 계산 가능 / 일부 요소만 / 계산 불가 | `conversion_rule`·`conversion_item`·`evaluation_component` |
| C. 과거 결과 비교 | 같은 조건 비교 가능 / 참고자료만 / 비교 불가 | `outcome` (+ `year_mapping`) |
| D. 합격 예측 | **검증된 모델·표본이 있을 때만.** 지금은 만들지 않는다 | 없음 |

A가 충족이어도 B·C·D를 자동으로 가능하다고 하지 않는다. 하나의 판정이 다음 판정을 끌어올리지 않는다.

---

## R1. 규칙 조회 키 — 대학 ID 하나로 찾지 않는다
- **필요 필드**: `academic_year`, `university_id`, `phase`/`round`/`admission_group`, `admission_name_raw`(+정규화), `program_id`, 지원자 유형(`scope_applicants`), 평가 단계(`scope_stage`/`stage_order`), 입력 점수 종류(`input_score_kind`).
- **통과 조건**: 조회 키 전부로 정확히 하나의 규칙이 선택되고 그 규칙의 `scope_status='confirmed'`.
- **실패 시 표시**: 규칙이 0개 → “이 전형의 반영 방법 자료 확인 필요”; 2개 이상 충돌 → “반영 방법이 여러 개라 계산하지 않음(원문 쪽 링크)”; 범위 불명확 → 계산 막음 + 사유.
- **확인할 사례**: 가천대 2027 수시 86~87쪽 실기성적표(`input_score_kind=practical`) vs 가천대 검정고시 반영 — 대학 ID 하나로 찾으면 실기표가 잡힌다(현행 `scoreEngine.js:376` 문제).

## R2. 입력 점수 종류가 맞지 않으면 계산하지 않는다
- **필요 필드**: `conversion_rule.input_score_kind` (ged_subject / ged_average / school_record / practical / essay / csat / unknown).
- **통과 조건**: 학생이 넣은 점수 종류 == 규칙의 입력 종류. 검정고시 점수는 `ged_subject|ged_average` 규칙에만.
- **실패 시 표시**: “이 표는 실기(논술) 점수용이라 검정고시 점수로 계산할 수 없어요.”
- **확인할 사례**: 가천대 86~87쪽(practical), 명지대 83쪽(ged_subject: 과목별 점수 → 등급).

## R3. 계산에 쓰는 규칙은 `calc_approval='approved'` 만
- **필요 필드**: `calc_approval`, `calc_block_reason`, `scope_status`, `review_status`, 근거(`evidence.value_status='confirmed'`).
- **통과 조건**: approved AND scope_status=confirmed AND review_status ∈ {main_crosschecked, human_confirmed} (에이전트 추출만으로는 부족 — 사람 확인 후 승인 권장).
- **실패 시 표시**: pending → “반영 방법 확인 중”, blocked → 사유 그대로.
- **현재 상태**: 이번 작업에서 approved 로 올린 규칙 수는 `reports/final_report.md` 참조. 대부분 pending 이다.

## R4. 계산 단계마다 공식 근거 — 중간 추정값 금지
- **필요 필드**: `formula_raw`, `formula_structured`, `operation_order`, `rounding_stage`, `rounding_mode`, `decimal_places`, `conversion_item`(band·subject_weight).
- **통과 조건**: 산출의 모든 단계(과목 선택 → 가중치 → 평균 → 반올림 → 구간표 → 점수식)가 원문 근거가 있는 필드로 재현된다.
- **금지**: 원문에 없는 선형 보간(`scoreEngine.js:492`), 등급 역산, ‘표준 추정등급’ 채우기, 최종 method 이름만 보고 승인.
- **실패 시 표시**: “일부 요소만 계산 가능(○○ 단계 공식 미확인)”.
- **분수선 위치를 반드시 확인한다.** 가산점·기본점수가 분자 안인지 나눗셈 바깥인지에 따라 결과가 크게 달라진다.
  확인한 사례: 명지대 2027 수시 83쪽(인쇄 81쪽) 교과 성적 산출식 — 가산점은 **나눗셈 바깥**이다(쪽 이미지 확대 확인).
  검정고시 만점(인문사회 국·수·영·사, 과목별 이수학점 8)일 때 바깥 `98+1.6=99.6` vs 분자 안 `(3136+1.6)/32=98.05`,
  1,000점 환산 시 **15.5점** 차이. 규칙 `conv:e58d136a500d76e1` 의 `operation_order` 에 단계가 적혀 있으니 그대로 따른다.
  텍스트만 보면 줄 순서 때문에 분자 안으로 읽히므로, 산식은 **쪽 이미지로** 확인한 것만 계산에 쓴다.
- **확인할 사례**: 동양미래대 2027 수시 17·20쪽 — 가중치(국수영4·사과3·한국사2·기가3·체육2·도덕/음악/미술1) → 평균 → 소수 첫째 자리 반올림 → 등급표 → `1055 − 55×등급`, 출결 대체, 정시는 다른 반영.

## R5. 구간표는 원문 경계 그대로, 계단형
- **필요 필드**: `input_lower/upper`, `lower_inclusive/upper_inclusive`, `output_grade`, `output_points`.
- **통과 조건**: 입력이 정확히 한 구간에 속함(겹침·빈틈은 `validate.py` 가 0 이어야).
- **금지**: 구간 사이 보간, 만점=1등급 가정.
- **확인할 사례**: 명지대 83쪽 — 검정고시 100점 → 3등급/98점. 1·2등급 칸은 ‘-’(검정고시로 도달 불가). “만점이어도 3등급”을 화면에 보여줄 수 있어야 한다.
- **열린 윗경계**: 원문이 ‘95이상’처럼 윗경계를 적지 않은 구간은 `input_upper=NULL` 로 원문대로 둔다. 계산기는 **정렬된 이웃 구간의 경계**(명지대: ‘100’ 구간이 따로 있으므로 95이상 = [95,100))로만 닫는다 — 이것은 원문 구간 순서에서 나오는 것이지 보간이 아니다. 이웃 구간이 없으면 닫지 말고 계산을 막는다.

## R6. 입시결과는 학과·세부전형 원행으로 — 대학·유형 중앙값 금지
- **필요 필드**: `outcome.university_id, result_academic_year, phase, admission_name_raw, program_name_raw, population_stage, metric, statistic_type, percentile_rank, component_scope, value_num, value_raw, unit, header_path`.
- **통과 조건**: 비교 대상 = 같은 결과 학년도·세부전형·모집단위·집단·측정항목·통계.
- **금지**: 대학 전체/교과 전체 중앙값을 특정 학과 커트라인으로(`rebuild_cutlines.py` 방식), 평균↔70%↔최저 바꿔 쓰기, ‘최종등록’을 최저로 해석, 70%컷을 70% 합격확률로 표현.
- **실패 시 표시**: “이 학과의 같은 기준 결과가 없어요(대학 전체 참고자료만)”.
- **확인할 사례**: 충남대 2026 수시 4쪽 — 최초합 High/Avg/Low, 최종등록자 교과환산 Avg/70%/Std, 최종등록자 등급 Avg/70%/Low/Std 가 각각 다른 행이고, 점수는 ‘면접 제외 교과성적’(`component_scope`).

## R7. 분류가 확정되지 않은 결과값은 비교에 쓰지 않는다
- **필요 필드**: `outcome.classification_status`, `result_academic_year`.
- **통과 조건**: `classification_status='auto_classified'` AND `result_academic_year` NOT NULL AND 사람이 표본 검수(현재 0건).
- **실패 시 표시**: 원표만 보여주기(원문 쪽 링크) — 숫자를 해석하지 않는다.
- **현재 상태**: 표 파서는 열 제목에 분명한 단어가 있을 때만 분류했다. 미분류·학년도 미정 수는 `validation_report.md`.

## R8. 점수 비교는 점수체계가 같을 때만
- **필요 필드**: `score_system_id`(아직 비어 있음 — 후속에서 정의), `full_score`, `component_scope`, 학년도, 산식 변경(`year_mapping.score_formula_changed`).
- **통과 조건**: 같은 학년도·같은 산식·같은 구성요소·같은 집단. 만점이 같다는 이유만으로 비교하지 않는다(`scoreEngine.js:898`).
- **실패 시 표시**: “산출 방식이 달라 직접 비교할 수 없어요.”
- **주의**: 2027 요강의 산식으로 2025·2026 결과를 다시 계산하지 않는다. 과거 요강·환산 규칙이 RAW에 없으면 “추가 자료 필요”.

## R9. 지원 학년도를 섞지 않는다
- **필요 필드**: `offering.academic_year`, `document_status`(확정요강/시행계획).
- **통과 조건**: 2027 지원 판정은 2027 확정요강 레코드만. 2028 시행계획은 별도 ‘예고’ 카드.
- **금지**: 2027 자료가 없다고 2028 로 판정(`analysis.js:93` 폴백), 시행계획 값을 확정으로 표시.

## R10. 수능최저는 구조화된 논리식으로
- **필요 필드**: `csat_minimum.minimum_exists, required_domains, candidate_domains, domain_count, grade_sum_limit, inquiry_as_one_domain, averaging_rule, history_condition, english_condition, logical_expression, calc_approval`.
- **통과 조건**: 학생이 필수영역 성적을 모두 입력 AND 논리식이 approved.
- **실패 시 표시**: 필수영역 미입력 → “판정 대기(○○ 성적 필요)”; 논리식 미확정 → “최저 기준 원문 확인”. 좋은 영역만 골라 통과시키지 않는다. 모의고사 계산은 ‘예상’으로만.
- **금지**: 탐구 2과목을 두 영역으로 세기, 국수영탐 좋은 N개 합 단순 규칙(`analysis.js:644`).
- **전형 하나에 규칙 하나로 두지 않는다 — 모집단위마다 다르다.** 확인한 사례: 가천대 2027 수시 43쪽(`doc:e1141b707380d054` page_index 42) '학생부우수자' 한 전형 안에서
  인문·자연/바이오로직스 = 사회·과학탐구 **1과목**, 의예과·약학과 = 과학탐구 **2과목 평균(소수점 절사)**, 한의예과 = 과학탐구 **2과목 모두 1등급**(평균 아님).
  같은 학생이 같은 전형에 지원해도 학과에 따라 통과 여부가 갈린다. 레코드: `csat:b82e77ca39bb0bb3`(인문·자연) / `csat:a72b09f08623df19`(바이오로직스) /
  `csat:183e84025d896666`(의예) / `csat:f662ae4764bb67ac`(한의예, 메인 확인) / `csat:081013dd7cb73b6a`(약학).
- **`averaging_rule` 이 비어 있으면 계산하지 않는다.** 탐구가 등장하는데 처리 방식이 비었다는 것은 '평균'이라는 뜻이 아니라 '아직 안 읽었다'는 뜻이다.

## R11. 자료 없음 ≠ 지원 불가, 학생 미입력 ≠ 대학 기준 미확인
- **필요 필드**: `eligibility_rule.ged_acceptance` (가능/불가/조건부/미확인), `coverage_gap.label`, `value_status`.
- **통과 조건**: 배지와 설명문은 같은 규칙 결과 하나에서 만든다.
- **표시**: 미확인 → “자격 원문 확인 필요”(불가 아님); 비공개(`coverage_gap.label='비공개'`) → “대학이 결과를 공개하지 않음”; 2026만 있음 → 그대로.
- **확인할 사례**: 명지대 학생부교과(학교장추천) — 검정고시 출신 지원 불가(추천 조건) vs 같은 대학 교과면접 — 가능. 대학 단위 ‘가능’으로 뭉치면 틀린다.

## R12. 학종·논술·실기·면접을 무시하지 않는다
- **필요 필드**: `evaluation_component.component, assessment_mode, stage_order, nominal_weight, selection_multiplier`.
- **통과 조건**: 정량(quantitative) 요소만 점수 비교. 정성(qualitative) 요소가 있으면 “점수만으로 판단 불가” 표시.
- **금지**: 학종에 GED 점수만으로 합격 라벨(`scoreEngine.js:1098·1124`), ‘학생부 100’=내신 100% 해석, 전형 이름만으로 유리함 판단(`analysis.js:156`).
- **확인할 사례**: 성균관대·서강대 학종(서류 100% = 정성 종합평가, 검정고시는 대체서식), 명지대 교과면접(1단계 교과 100% 5배수 → 2단계 1단계 70%+면접 30%).

## R13. 합격확률·안정권을 만들지 않는다
- 검증된 합불 표본·모델 없이 확률·안정/적정 라벨 금지. 대학 전체 검정고시 합격자 수(예: 서울대 수시 10명)는 개인 합격확률이 아니다. 합격 사례만으로 난이도 추정 금지.

## R16. 같은 표 안에 계열·전형별로 줄이 여러 개일 수 있다
- **필요 필드**: `conversion_item.subject`, `conversion_rule.scope_admissions`/`scope_programs`.
- **확인한 사례**: 충남대 2027 수시 90쪽(인쇄 89쪽) 검정고시 합격자 교과성적 산출표는 한 표 안에
  `과목별반영점수(인문·자연계열)` 75/65/55/45/35/25/20 과 `과목별반영점수(예체능계열)` 75/70/65/60/55/50
  **두 줄**이 있다. 같은 점수 구간이지만 결과가 다르다.
- **통과 조건**: 학생의 계열에 맞는 줄을 골라야 한다. `subject` 가 비어 있으면 어느 줄인지 알 수 없으므로 계산하지 않는다.
- **금지**: 첫 줄만 읽고 전 계열에 적용, 두 줄을 평균내기.

## R15. 0 은 값이 아니라 '미공개' 표기일 수 있다
- **필요 필드**: `outcome.value_raw`, `value_num`, `metric`, `document.original_or_substitute`.
- **확인한 사례**: 대학어디가 결과공개 HTML 표(`document.manifest_note='대학어디가 결과공개 HTML 표(대체)'`)는 공개하지 않은 칸을 빈칸이 아니라 `0.0` 으로 적는다.
  영남대 2025 통합 결과(`doc:9bcb444ac61d353b`) 약학부 행은 환산점수·환산등급이 전부 `0.0` 이다 — 실제로 0점을 받은 것이 아니다.
- **통과 조건**: 등급 지표는 1~9, 백분위는 0~100, 환산점수는 `full_score` 안. **범위 밖 값은 계산·비교·그래프에 넣지 않는다.**
- **금지**: 0 을 '가장 낮은 값'·'가장 쉬운 학과'로 해석, 0 을 섞어 평균 내기(대학 평균이 통째로 내려간다).
- **표시**: “이 학과는 대학이 수치를 공개하지 않았어요(원표에는 0으로 적혀 있음)”.
- **현재 규모**: `validation_report.md` 의 ‘값 범위 의심 목록’ 참조. 환산등급 0 은 등급 체계상 존재할 수 없으므로 전량 미공개 표기로 본다.

## 앱에 바로 쓰면 안 되는 자료 (요약)
1. `calc_approval != 'approved'` 인 모든 환산·최저 규칙.
2. `review_status='held'` 이거나 근거 `value_status!='confirmed'` 인 모든 레코드.
3. `outcome.classification_status='pending'` 이거나 `result_academic_year IS NULL` 인 결과값.
4. `candidate` 테이블 전체(자동 후보 구간 — 사실이 아님).
5. 대체 자료(`document.original_or_substitute='대체'`) 결과는 ‘대학 원문 아님’ 표시 없이 쓰지 않는다.
6. 2028 시행계획(`document_status='시행계획'`)을 2027 판정에.
7. 기존 앱 JSON 의 값과 섞어서 빈칸 채우기.
