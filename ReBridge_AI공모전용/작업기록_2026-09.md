## 1. 출발점 — 무엇이 잘못돼 있었나

서연님 보고: **"검고 3등급이 나와도 가천대 안정, 5등급이 나와도 가천대 안정"**
동근님 지적: **"성균관대·서강대가 적정으로 뜬다. 일각에서는 명지대·충북대 정도가 최선이라고 한다."**

재현해서 원인을 셋 찾았다.

### (1) 대학이 공개하지 않은 환산 기준을 앱이 지어내고 있었다
`scoreEngine.applyComparativeConversion()`이 환산표가 없으면 `method:'standard'`로
**다른 대학 표의 중앙값**을 써서 등급을 만들었다. 성균관대·서강대는 검정고시 비교내신
환산표를 공개하지 않는데(`comparativeGradeType: 'prose'`), 앱이 대신 등급을 만들어
합격선과 비교하고 "적정"이라 했다. **대학이 안 밝힌 기준을 우리가 만든 것.**

### (2) 자격 요건이 따로 있는 전형에 일반전형 합격선을 붙이고 있었다
가천대 2027 수시에서 검정고시로 지원 가능한 전형은 **논술 2개 + 학생부종합 3개**뿐이고,
그 셋이 전부 교육기회균형·기회균형·특성화고졸재직자였다. 즉 자격이 안 맞으면
사실상 수시 지원 자체가 안 되는 대학인데, 앱은 거기에
**'가천대 학생부종합 전체 합격자 70%컷 3.79등급'**을 붙여 "안정"이라 했다.

### (3) 칸수 라벨 하나가 1.3등급을 덮고 있었다
옛 기준 `gap ≤ -1.0 안정 / ≤ 0.3 적정 / ≤ 1.0 소신 / ≤ 2.0 도전`.
가천대(합격선 3.79)에서 90점(3등급, gap −0.93)과 80점(4등급, gap −0.04)이 **똑같이 '적정'**.
이게 서연님이 본 현상이다.

## 2. 판정 기준을 어떻게 바꿨나 (기준값 전문)

### 2-1. 칸수 구간 — `src/lib/scoreEngine.js` `CHANCE_BANDS`

| gap 범위 | 라벨 | 옛 기준 |
|---|---|---|
| ≤ −1.2 | 안정 | ≤ −1.0 |
| ≤ −0.4 | 적정 | ≤ 0.3 |
| ≤ 0.2 | 소신 | ≤ 1.0 |
| ≤ 1.0 | 도전 | ≤ 2.0 |
| 그 외 | 어려움 | (없었음) |

`gap = 내 환산등급 − 합격선등급` (+면 부족)

**근거 1 — 우리가 쓰는 합격선이 무엇인지 확인했다.**
`cutlines_2026.json`의 **298개 블록 전부가 70%컷**이다(`cutGradeAvg`는 **0개**).
70%컷 = 합격자를 성적순으로 줄 세웠을 때 상위 70% 지점. 즉 합격자의 70%가 이 등급보다
우수했고 30%만 이보다 아래였다는 뜻 → **'합격자 평균'이 아니라 분포의 아래쪽 경계**다.
그래서 gap = 0 은 "떨어진다"가 아니라 "합격자 하위 30% 언저리" = **소신**이다.

**근거 2 — 검정고시생에게만 있는 손실.**
70%컷은 일반고 학생의 교과 등급 분포다. 검정고시생이 비교내신으로 같은 등급을 받아도
같은 자가 아니다. 학교생활기록부가 없어 출결·봉사 비교과를 대학이 정한 대체 기준으로
받고(모집요강마다 다름), 서류평가도 대체서식으로 받는다. **그 축의 자료는 우리에게 없다.**

**근거 3 — 두 실수의 비용이 다르다.**
느슨한 쪽이 틀리면 학생이 지원 기회를 날린다. 짠 쪽이 틀리면 한 칸 더 안전하게 쓸 뿐이다.

> ⚠️ 이 기준을 다시 느슨하게 하려면 **검정고시생 실제 입결**을 먼저 가져와야 한다.
> 지금 그 자료는 공개된 곳이 없다(§7 참조).

`verdictFromGap()`도 같은 경계로 맞췄다. 예전엔 4단계뿐이라 gap이 아무리 벌어져도
'도전'에서 멈춰서, 카드 게이지는 '어려움'인데 설명문은 "도전 지원이에요"인 모순이 있었다.

### 2-4. 학생부종합은 '안정'을 주지 않는다

`if (ev.isHolistic && band.level === 5) band = 적정`

어디가의 학생부종합 70%컷은 **서류평가를 통과한 뒤** 합격한 학생들의 교과 등급이다.
검정고시생은 그 서류평가를 학생부가 아니라 **대체서식**으로 받는다. 교과 등급이 좋아도
통과 여부를 우리가 알 수 없으므로 '안정'이라고 말할 근거가 없다.
칸수를 아예 없애지는 않았다 — 등급이 낮으면 어차피 어렵다는 정보는 여전히 맞다.

### 3-2. 2028학년도 5등급제 (comparative_2028 연결 — 그전까지 **사용처 0곳**)

2028 시행계획 **188곳 중 62곳이 5등급 체계를 적었고, 그중 45곳은 9등급 표를 함께 둔다**
(보통 5등급 = 2028년 이후 졸업자, 9등급 = 2027년 이전 졸업자).
**검정고시 출신자에게 어느 표를 적용하는지 안 적은 대학이 더 많다.**

공개된 5등급 표는 구간이 훨씬 좁다 — 전부 대학이 낸 표에 적힌 값:
- **성공회대**: 검정고시 100점 → **2등급**, 96.99점 이하는 전부 5등급
- **국립금오공대**: 90점 이상 → 3등급, 60점 미만은 **등급 자체가 없음**
- **상명대**: 5등급 환산점수 `100/95/93/70/0` (9등급표는 `100/98/96/94/90/80/60/40/0`)

→ `src/lib/comparative2028.js` 추가. **판정하지 않고 '무엇이 적혀 있나'만** 돌려준다.
→ `FiveGradeBlock`(DetailScreen) + '이 목록 읽는 법'에 표시.

> ⚠️ 앱은 지원 학년도를 묻지 않는다. 그래서 "2028 지원은 계산 안 한다"고 쓰면 거짓말이 된다.
> 칸수의 기준이 무엇인지 밝히고, 2028 지원자는 그대로 쓰면 안 된다고만 말한다.

### 3-3. 전문대학 전형 (119곳 / 282행)

`admissions.json`의 전문대 138곳은 **전 대학이 똑같은 두 줄**이었다
('수시 일반전형' + '정시 수능위주', 문구까지 동일, `status: 'baseline'`).
출처도 **대교협(KCUE)**으로 적혀 있었는데 전문대 기본사항을 내는 곳은 **전문대교협(KCCE)**이다.

`data-pipeline/v2/README.md`(543행)가 이미 지적해 둔 문제였다:
> 기본사항의 검정고시 원칙 조항은 협의회 공통 규정이라, 대학 단위로 넣으면
> 실제로 확인 안 된 138개 대학 전부에 '가능'을 지어내는 꼴이 된다.

파이프라인은 그래서 안 넣었는데 **앱 데이터에는 들어가 있었다.**

대학별 전형방법 엑셀은 저장소에 없다(gitignore). 대신 이미 있던
**전문대교협 전형결과**(`cutlines_college_2026/2025.json`)가 그 대학이 실제로 어떤 전형으로
뽑았는지를 담고 있어서 그걸 읽었다.

| 신호 | 뜻 |
|---|---|
| `일반(서류)` 블록 있음 | 그 해 수시 일반전형으로 뽑았다 |
| `byType`에 `특별전형 …` 있음 | 그 해 수시 특별전형으로도 뽑았다 |
| `수능위주` 블록 있음 | 그 해 정시로 뽑았다 |

결과: **119/138곳 · 282행** (수시 일반 90 · **수시 특별 81** · 정시 111).
수시 특별전형 81행은 **앱에 아예 없던 전형**이다. `gedEligible: '조건부'` +
`specialEligibility: true`로 칸수도 막는다(만학도·특성화고·기회균형 묶음 이름이라).
근거 없는 19곳은 지어내지 않고 안내만 두되 출처를 전문대교협으로 바로잡았다.

> ⚠️ 합격선은 **지난 학년도 결과**다. 그 전형으로 뽑은 기록이 있다는 뜻이지 올해도 뽑는다는
> 보장이 아니다. 생성되는 모든 행의 `note`에 그 사실이 박혀 있다 — 빼지 말 것.
> ⚠️ 전문대교협 자료는 **공공누리가 아니다**(무단 복제·배포 금지). 학과 단위 원본은 싣지 않고
> **대학×전형 집계값만** 쓴다. 이 방침을 깨지 말 것.

생성기: `scripts/buildCollegeAdmissions.mjs` → `src/data/admissions_college.json`

### 3-4. 모집요강 원본 링크 (171곳)

## 4. 화면 — 새로 만들거나 크게 고친 것

### 4-1. `GuidelineCheck` — "모집요강에서 확인하기" 토글
대학 상세 머리말 + 전형 카드 두 곳. 내용: 모집요강 원본 PDF(수시 먼저) · 입학처 ·
검정고시생이 직접 봐야 할 5가지(지원자격/비교내신/대체서식/수능최저/일정) · 이 전형의 출처 ·
**"앱과 모집요강이 다르면 모집요강이 맞아요."**

### 4-2. `AdmissionMatrixScreen` — "전형별 지원 가능 여부" (신설 화면)
**345개 대학 · 3,529행 (가능 3,192 · 조건부 156 · 불가 181)**

왜 필요했나: 자료가 두 벌인데 앱이 한 벌만 썼다.
- 2027 대교협 자료 = '지원 **가능한** 전형'만 모은 목록 → **'불가' 행이 0건**
- 2028 시행계획 = 전형 전체 목록 → '불가' 187건

2027 자료가 있는 대학은 2028을 '참고' 칸으로 밀어내므로, **195개 중 95개 대학에서
"이 전형은 검정고시로 못 간다"는 정보가 화면에 아예 닿지 않고 있었다.**
(명지대 학생부교과(추천형) = 학교장 추천 필요 → 불가)

> ⚠️ 두 학년도를 **합치지 않는다.** 전형명이 서로 달라(2027 '학생부교과(일반전형)' vs
> 2028 '학생부우수자') 이름으로 짝지으면 없는 대응을 만들어낸다. 유형으로만 묶고
> 행마다 학년도를 붙여 나란히 보여준다.
> ⚠️ **2027에 없다고 '불가'로 쓰지 않는다.** 그 자료는 195개 대학만 싣는다.

필터: 전체 / 지원 가능 / 조건부·불가 × 전체 / 수시 / 정시.
수시·정시가 자료에 없는 행 805건은 '수시/정시 미상'으로 표시하고, 필터 시 몇 개가
빠졌는지 알린다(빈칸으로 두면 정시로 오해한다).

### 4-3. 목록 화면 '전형' 필터가 대학을 숨기고 있었다
카드에 보이는 **대표 전형 1개(`bestType`)**로만 걸러서, 학생부교과 전형이 있어도
대표가 학생부종합이면 '교과' 필터에서 통째로 사라졌다.

| 필터 | 수정 전 | 수정 후 |
|---|---|---|
| 학생부교과 | 72곳 | **150곳** |
| 논술 | **3곳** | **44곳** |
| 실기 | 0곳(옵션도 없음) | **140곳** |
| 수능위주 | 29곳 | **323곳** |
| 특별전형 | 0곳 | 81곳 |

→ `availableTypes`(그 대학에서 검정고시로 가능한 전형유형 전부)로 필터. 실기 옵션 추가.

### 4-4. 합격선 신뢰도 고지 (가천대 문제 전 대학 점검 결과)

**[A] 자격 제한 전형밖에 없는 대학 8곳** — 가천대 · 홍익대 · 연세대(미래) · 부산대 ·
강남대 · 한국기술교육대 · 예원예술대 · 한서대. 대학 상세 맨 위에 배너.

**[B] 합격선 하나를 여러 전형이 나눠 쓰는 조합 63개** — 어디가 입결이 '대학 × 전형유형'
단위 집계라서 생긴다. 충남대 학생부종합은 **11개 전형이 전부 3.39등급**, 세종대는 성격이
전혀 다른 사이버국방 특별전형까지 같은 2.635.
**자료를 더 잘 구해서 고칠 수 있는 게 아니라 원천의 해상도 문제다.**
→ 합격선 숫자 바로 아래 `.adm-cut-caveat`로 "이 합격선은 OO대 학생부종합 전형 11개를
통틀어 집계한 값" 표시.

**[C] 학과 1~3개로 낸 합격선 28건** — 광주가톨릭대·대전가톨릭대·추계예술대는 **학과 1개**.
→ 같은 자리에 "대학 전체를 대표한다고 보기 어려워요".

## 5. UI 작업 (서연님 요청)

6개 요청: 덜 AI스럽게 · 시작 화면 신설 · 한 페이지에 다 넣지 않기 · 대학 목록 여백 ·
색깔 이모지 아이콘 · 둥근 폰트.

- **폰트**: CDN(jsdelivr 차단) → npm 번들. SUIT → Wanted Sans + Jua → **Wanted Sans 단일**
  (서연님: "Jua 너무 두꺼워"). 렌더 폭 측정으로 실제 적용 검증.
- **색**: 'A 따뜻한 크림' 시안 적용. 진한 파랑 채움 버튼 → 연노랑(`--grad-brand: #FFE9B0`).
- **대비**: 크림 전환 후 남은 흰 글자·흐린 글자 **80건 → 0건** (Playwright 계산 스타일 감사).
  `--text-sub: #736C5E`, `--text-muted: #767062`로 조정.
- **온보딩 신설**: 인사 → 나이 → 상황. "만 나이로 골라주세요", 로그인 없음·기기 저장 고지.
- **꿈드림 나이**: 서연님 지적("17세가 아니라 17세 이하/이상 아니야?")이 **실제 로직 버그**를
  드러냄. `dreamdrimEligible`(2상태) → `dreamdrimEligibility`(yes/partial/no 3상태).
  기준 만 9~24세를 먼저 말하고, 구간이 걸치면 단정하지 않는다.
- FAQ 카드 4개가 전부 용어 목록으로 가던 것 → 각각 `guide`의 `types`/`susi`/`compare`/`csat`로.
- 하단 탭 아이콘: 색깔 이모지 → lucide 선 아이콘(서연님 재요청).

## 9. 앞으로 지킬 것 (요약)

1. **근거 없는 숫자를 만들지 않는다.** 환산표가 없으면 칸수를 내지 않는다.
   `conversionMethod === 'standard'`에서 다시 칸수를 내지 말 것.
2. **칸수 기준을 느슨하게 바꾸지 않는다.** 바꾸려면 검정고시생 실제 입결을 먼저 가져올 것.
3. **두 학년도 자료를 합치지 않는다.** 전형명이 다르면 없는 대응이 생긴다.
4. **2027 자료에 없다고 '불가'로 쓰지 않는다.** 그 자료는 가능한 것만 싣는다.
5. **전문대교협 자료는 대학×전형 집계값만 쓴다.** 공공누리가 아니다.
6. **환산표를 넣을 때는 대학이 '등급'이라고 쓴 것만.** 값이 그럴듯해도 안 된다.
7. 자격 제한 전형은 **목록에서 빼지 말고** 칸수만 안 낸다.
